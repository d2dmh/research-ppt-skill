### 配图的“三层表达”——提示词交给网页端写

自己写提示词时，三张图出来“完全没区别”（用户原话），都是“左侧设备 + 中部框 + 右侧箭头”。

② 把它写的提示词**原样**贴到另一个新会话里逐张生图。它自己排出了三类表达：
**概念图**（只讲机制，不画设备内部）→ **原理图**（讲能流转换与方向）→ **平面总平面图**（讲实体空间与管网）。
这条已写进 `references/visuals.md` 第二节。

### 公式脚标：多字符下标会让备用文本变丑

`omml.py` 的线性备用文本里，**多字符下标会被加括号**：`\eta_{chp}` → `η_(chp)`，看着像命令残留；
多字符上标会带花括号（`^{net}`）。换成**单字母脚标 + 一行符号说明**最干净：
`L_t^{e} = \eta_c P_t^{c} + P_t^{h} + P_t^{b}` 渲染成 `L_t^e = η_c P_t^c + P_t^h + P_t^b`。
另外注意：**先下标后上标**（`L_t^{e}`）比反过来（`L^{e}_t`）干净；目标函数那类长公式拆成两行比缩字号好。

### 一、公式：只用 layouts.md 列出的 LaTeX 子集

`omml.py` 会给公式包一层 `mc:AlternateContent`：PowerPoint 显示真正的分式，其余渲染器显示**线性 Unicode 备用文本**。
**子集之外的命令会在备用文本里漏出原文或变成方框**：实测 `\mathbf{x}` 渲染成 `mathit{x}`、`\quad` 变成一个方框；
而 `\in`、`\{ \}`、`\frac`、`\sqrt`、`\sum`、`\max`、`\hat`、`\rho`、`\bar`、`\varepsilon` 都正常。
所以写完必须看渲染图：不用 `\mathbf`（直接写 `x`）、不用 `\quad`（用普通空格），也不要用 `\ldots` 以外的省略号写法。

### 二、窄栏字数上限（加内容时最容易碰到）

自动换行拆词全部出在窄栏。可用宽 = 槽宽 − 2×0.2，实测一行能放：

| 位置 | 槽宽 | 字号 | 一行约能放 |
|---|---|---|---|
| `framework5` 的 m1 / m4（高窄列） | 2.62 / 2.55 in | 14pt | **约 10 个汉字** |
| `framework5` 的 m2 | 3.17 in | 14pt | 约 13 个汉字 |
| `framework5` 的 m5 | 3.77 in | 14pt | 约 16 个汉字 |
| `three_columns` 左/中/右 | 3.55 / 4.8 / 3.8 in | 15pt | 约 14 / 21 / 16 个汉字 |
| `results_side` 右侧解读栏 | 3.7 in | 15pt | 约 15 个汉字 |

超出的用改短句子解决，不要缩字号。15 页成套稿里第一轮 lint 报了 17 条警告（拆词 + 孤行），逐条改短后归零。

### 三、长稿的内容 JSON 分两部分写、再合并

一次写完 15 页的 JSON，一处语法错就废掉整个文件，也不方便反复小改。做法：
`content-part1.json`（封面～第 8 页）、`content-part2.json`（第 9 页～末页，只写 `{"slides":[...]}`），
用三行 Python 合并成 `content.json` 再生成。实测改了 4 轮（补模块内容、改公式、补满留白），每轮只改对应那份、重新合并。

### 四、GPT 生图：一次多要，逐张读字节、算哈希去重

一次向网页端要三张不同图位的示意图（写明「三张各自独立、不要拼版、图上不要文字」）——它一次全出完。
页面里会出现多个 `blob:` 图（本次 4 个 img，其中两个是同图重复），**必须逐张读字节算 sha256 去重**，
再按尺寸和内容认图。三张都跑 `verify_asset_origin.py` 确认 C2PA 出处为 `gpt-image`。

**出图常带大片白边**，不裁的话放进图位会缩得很小。裁白边（保留原图）：

```bash
~/.venvs/ppt/bin/python -c "
from PIL import Image, ImageChops
im = Image.open('images/x.png').convert('RGB')
diff = ImageChops.difference(im, Image.new('RGB', im.size, (255,255,255))).convert('L')
b = diff.point(lambda v: 255 if v > 8 else 0).getbbox()
im.crop((b[0]-16, b[1]-16, b[2]+16, b[3]+16)).save('images/x-crop.png')"
```

实测三张：1672×941 裁后 1672×619、1774×887 裁后 1738×857、1916×821 本来没白边。裁完按比例放进 `contain` 图位即可。

### 测试与发现

用“未来气象文件生成方法（Future EPW Generator）”7页测试稿跑了一遍原流程，发现以下问题：

1. `formula()` 直接写 `a14:m`，没有 `mc:AlternateContent` 和备用文字，在LibreOffice/WPS里公式整块空白。
2. 折线图纵轴固定从0开始，温度从24升到26 °C这类变化在图上看不出来。
3. `diagram` 总是画箭头，节点文字顶部对齐，节点矮的时候文字压到箭头上。并列关系会被误画成先后流程。
4. 每页都要手算坐标，大部分时间花在对齐上；渲染只能用Windows版PowerPoint；字号低于投影可读下限（注释8pt、图表10pt）；不写 `brand` 也会默认显示厦大logo；目录页没有实现“已讲章节变灰”。

### 修改

- 公式：标准的 `mc:AlternateContent`（Office公式加线性Unicode备用文字）。新增 `omml.py`，把LaTeX子集转成原生OMML，支持分式、上下标、根号、重音符号；用pandoc把生成的OMML读回LaTeX，结构正确。
- 图表：新增 `min`/`max`、坐标轴标题、数据标签、数值格式、`stacked`/`barh` 两种图型；字号默认12pt；加浅灰网格线；折线加标记点。
- 流程图：`edges: []` 表示并列；`arrows: false` 只画线；节点文字垂直居中；连线方向自动判断。
- 新增版式模板（`layouts.py`，9种版式加结论卡）：区域内自动堆叠，文本、公式、表格按内容量高度，图表平分剩余空间；支持 `row` / `grid` / `stack`。7页测试稿全部用模板生成，内容JSON里没有一个坐标。
- 新增 `paper_figure`：论文原图原生裁切出子图，不加灰框，可标(a)(b)。
- 新增 `lint.py`：估算溢出、孤行、小字号、文字与图表或文字之间的重叠、越界、未替换的图位；含分式的公式只给提示。
